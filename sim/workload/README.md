# sim/workload

The spec Section 5 workload model. A seeded, reproducible generator that emits
`(arrival_time, Flow)` pairs -- the `WorkloadSource` the engine consumes.

- `distributions.py` - `LognormalSpec` (median/p95 -> mu/sigma), sampling helpers.
- `flow_structure.py` - `ClassSpec` and `generate_flow`: per-flow invocation count,
  per-step input/output tokens, accumulated KV context, inter-invocation tool-time
  gaps; runaway amplification.
- `arrivals.py` - non-homogeneous Poisson arrivals: diurnal modulation + burst
  episodes, generated by thinning.
- `mix.py` - calibrates the per-flow class probability so the achieved
  token-volume share matches the target (spec mix is by token volume, not flows).
- `generator.py` - `WorkloadGenerator`: combines all four. Re-iterable and
  deterministic (same seed -> byte-identical workload).
- `validation.py` - empirical stats, distribution plots, workload hash (used by
  the SG2 validation report; run `make validate`).

## Parameters

All parameters live in `../configs/workload.yaml`, each annotated `spec Section 5`
(given in the frozen spec) or `ASSUMPTION` (spec fixes the family/behavior, not the
value -> swept in sensitivity). Nothing is hard-coded.

## What the engine honors today

`context_tokens` (KV growth) drives the KV reservation now. `gap_after_s`
(inter-invocation tool-time) is carried as workload data; the engine begins
honoring the gap at SG3, when policies run mixed multi-invocation workloads.
